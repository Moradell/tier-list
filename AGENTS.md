# Правила работы с репозиторием

Перед изменениями прочитайте относящиеся к задаче документы:

- [Архитектура](.agents/architecture.md)
- [Данные книг и история](.agents/data.md)
- [Рабочий процесс и проверки](.agents/workflow.md)

## Основные правила

1. Соблюдайте направление зависимостей `app → pages → widgets → features → entities → shared`.
2. Не складывайте всю книжную функциональность в один slice `books`: книга является entity, а действия над ней — features.
3. Импортируйте slices через публичный `index.ts`. Исключение — Node scripts и Vite plugins, которым нельзя загружать UI/SCSS через barrel-файл.
4. Не переносите предметные функции в `shared` только из-за возможного переиспользования. `shared` не должен знать о книгах, тирах и LiveLib.
5. Не меняйте формат CSV без синхронного обновления Zod-схемы, CLI-проверки и dev API.
6. Порядок книг в CSV является пользовательскими данными. Не переупорядочивайте книги внутри тира без явного запроса.
7. DnD и запись файлов должны оставаться dev-only. Production и GitHub Pages работают только на чтение.
8. Не добавляйте `BACKLOG.md` в Git: это локальный файл пользователя.

## Обязательная проверка

После изменений запускайте проверки, соразмерные задаче. Для архитектурных,
данных и DnD-изменений обязательны:

```bash
npm run typecheck
npm run books:validate
npm run build
git diff --check
```
