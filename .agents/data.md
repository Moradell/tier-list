# Данные книг и история

## JSON

Файлы находятся в `data/books/`:

- `novels.json`
- `stories.json`
- `manga.json`
- `unranked.json`

Схема определена в `src/entities/book/model/books.ts`.

```json
{
  "tier": "S",
  "position": "1",
  "title": "Название",
  "author": "Автор",
  "user_rating": "5",
  "livelib_rating": "4.5",
  "url": "https://www.livelib.ru/book/...",
  "cover": "/covers/example.jpg",
  "year": "2020",
  "read_date": "2024-01-31"
}
```

Правила:

- `tier`: только `S`, `A`, `B`, `C`, `D`, `F`.
- `position`: положительное целое число строкой.
- В рейтинговых JSON-файлах позиция начинается с `1` внутри каждого тира.
- Тиры располагаются в порядке `S → A → B → C → D → F`.
- В `unranked.json` позиция сквозная для всего файла.
- Порядок объектов внутри тира — пользовательский и не должен меняться случайно.
- `read_date`: `YYYY-MM-DD`, `YYYY-MM` или `-`.
- Обложки хранятся локально в `public/covers`.

После ручных изменений используйте:

```bash
npm run books:validate
```

`npm run books:sort` является изменяющей командой: она сортирует файлы и
пересчитывает позиции.

## История

`data/books/history.json` содержит:

- `knownBookIds` — базовую отметку уже известных книг;
- `events` — события `move` и `new`.

Не добавляйте текущую библиотеку как 107 событий `new`. Новое событие создаётся
только для ID, которого ещё нет в `knownBookIds`.

Событие хранит snapshot названия, автора, обложки и URL, чтобы история оставалась
читаемой после удаления или замены книги.

## Фильмы и сериалы

- `data/movies/movies.json` содержит записи с `kind: "film"`.
- `data/movies/series.json` содержит записи с `kind: "series"`, кроме аниме.
- `data/movies/anime.json` содержит записи с `kind: "series"` и `genre: "аниме"`.
- `data/movies/catalog-meta.json` генерируется командой `npm run movies:meta` и содержит счётчики табов.
- `data/movies/history.json` хранит известные `kp_id` и события добавления новых записей.
- `countries`, `directors` и `actors` обогащаются пакетно из Wikidata по `kp_id` командой `npm run movies:enrich`.
- Оставшиеся пропуски у обычных фильмов заполняются через Kinopoisk Unofficial API командой `npm run movies:enrich:kinopoisk`; мультфильмы и аниме команда пропускает, а токен `KINOPOISK_API_KEY` хранится только в `.env.local`.
- Обогащение не перезаписывает уже заполненные массивы и сохраняет порядок записей каталога.
- Порядок объектов является пользовательскими данными и сохраняется при импорте.
- Три файла загружаются раздельно только при открытии соответствующего подраздела.
- Перед `dev` и `build` метаданные пересчитываются, а киноистория синхронизируется автоматически.
- Текущий каталог является базовой отметкой и не добавляется в историю ретроактивно.
- Для новой записи дата берётся из `added_at`, а при её отсутствии — из времени синхронизации.

## Dev API

Dev-only API реализован в `vite/plugins/booksApi.ts`.

- Запись выполняется последовательно.
- JSON-файлы заменяются через временный файл.
- Изменения данных не должны запускать HMR и сбрасывать состояние.
- API отсутствует в production.

## Фотографии авторов

- Локальные изображения находятся в `public/authors/`.
- Соответствие имени автора локальному файлу хранится в `data/books/authors/files.json`.
- Страницы-источники и сведения о происхождении изображений хранятся в `data/books/authors/photos.json`.
- Если точного изображения нет, интерфейс использует `public/authors/placeholder.svg`.
- Не подставляйте сомнительное совпадение только ради заполнения фотографии.
